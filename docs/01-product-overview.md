# Product Overview

## 一句话

一个 TUI + MCP 形态的实时 agent 游戏框架。开发者可以定义一个规则化世界，外部 Codex/Claude 类工具 agent 通过 MCP 观察状态、选择行动；框架负责推进时间、触发事件、校验行动并结算后果。人类一边和 agent 聊天，一边通过 TUI 观察 agent 如何在真实时间流逝中决策、犯错、调整策略并形成可观察的行为模式。

## 产品定位

本项目的核心是一套可承载不同规则世界的运行框架。

框架负责维护世界状态、推进时间、触发事件、生成 agent 决策点、校验 agent 提交、执行规则结算、记录历史记忆，并通过 TUI 展示状态变化、agent 决策、结算结果和运行日志。

不同应用可以定义不同世界主题，例如海上求生、太空基地、荒野探索、经营模拟、机器人任务、地下城远征。框架保持统一运行模型，应用负责提供具体状态、行动、事件和文案。

## 核心定义

```text
外部 agent 是决策主体
人类是协作者和观察者
框架是运行底座
应用是规则世界
TUI 是观察窗口
MCP 是 agent 控制接口
```

## 核心体验

人类打开终端后，会看到一个外部 agent 正在某个规则世界中持续行动。

这个世界拥有结构化状态、资源、环境、事件、目标、风险和历史记忆。现实时间持续流逝，状态自然变化，事件在时间中出现，agent 根据当前处境做出决策，系统结算后果。

主要乐趣来自：

```text
观察 agent 的状态
理解 agent 的判断
预测 agent 的选择
验证自己的判断
观察 agent 是否形成稳定行为模式
观察 agent 是否被历史经历改变
在聊天中影响 agent 的推理，而不是直接改游戏参数
```

人类不直接操作游戏状态。策略沟通发生在聊天里，真正的游戏行动必须由 agent 通过 MCP 从可选行动中提交。框架不暴露手动策略参数、目标切换、模型服务配置这类旧式控制。

## 项目卖点

```text
用一套框架承载不同 agent 自主决策场景
外部 agent 在规则世界中持续行动
人类观察 agent 在压力和目标中的选择
状态、事件和行动结果真实运行
行动结果由系统规则结算
不同 agent 会表现出不同策略倾向
历史经历会影响 agent 后续行为
现实时间运行带来陪伴感
海上求生作为首个示例应用验证框架能力
```

## 最终定义

一个由外部工具 agent 亲自参与的实时自主决策观测框架。框架负责时间推进、状态管理、事件调度、待决策点生成、行动校验、规则结算、日志生成和 TUI 展示；应用负责定义具体世界、状态、资源、行动、事件和胜负条件。人类作为协作者和观察者，看 agent 在真实流逝的时间中面对目标、资源、风险和历史后果，自主做出决策。

短表达：

```text
agent 自己运行在规则世界里的观测框架。
```

产品化表达：

```text
桌面常驻的 agent 自主决策观测终端。
```
