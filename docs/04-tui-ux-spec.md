# TUI UX Spec

## TUI 方向

第一版使用 TUI 验证核心体验。界面应呈现为 agent 生存观测站、航海记录终端、黑匣子监控界面。

TUI 必须支持中文和中英文混排。所有布局、截断、换行、上浮提示和表格对齐都以终端显示宽度为准，不能用字符串字符数直接计算宽度。

TUI 主要区域：

```text
顶部概览：模型、运行时长、生存天数、当前时间
状态面板：HP、饥饿、口渴、体力、士气、木筏耐久
资源面板：食物、淡水、木材、纤维、工具
环境面板：天气、海况、风向、风险等级、距离陆地
Agent 面板：当前目标、主要担忧、agent 等待状态、可选行动
决策列表：最近几次 agent 选择和结果
日志窗口：简短航海日志
控制区：暂停、继续、退出
Activity：由 UiEvent 派生的近期变化流
```

## 视觉与动效原则

TUI 应保持灵动感：界面需要持续表达世界正在运行、状态正在变化、agent 正在判断。动效服务于可观察性，布局骨架保持稳定，所有变化都遵循统一规则。

```text
布局稳定：主要面板位置固定，避免因为内容变化导致整体跳动
局部更新：优先刷新发生变化的区域，减少整屏闪烁
动效克制：动效用于提示变化，不持续抢占注意力
规则统一：同类信息始终使用同一套颜色、符号、动效和持续时间
信息分级：普通信息、重点信息、危险信息、临时提示使用不同层级
```

## 信息层级

```text
一级信息：当前危险、重大事件、agent 当前行动、失败或濒死状态
二级信息：核心状态、关键资源、天气海况、风险等级、下一事件倒计时
三级信息：最近决策、简短日志、性格倾向、历史摘要
四级信息：运行时长、模型名、普通环境描述、低优先级系统提示
```

展示规则：

```text
一级信息使用高对比色和短时动效
二级信息保持常驻可见，变化时短暂高亮
三级信息以稳定可读为主，新增内容淡入或滑入
四级信息低对比展示，避免争夺注意力
```

## 文本样式规则

```text
标题：统一大写或统一中文短标题，使用边框线或固定色强调
普通内容：低饱和、稳定颜色，便于长时间观看
重要内容：亮色高亮，持续时间短，随后回到常规状态
危险内容：黄色、橙色、红色分级，风险越高对比越强
agent 决策理由：独立于日志展示，使用次重点样式
日志正文：可读性优先，避免频繁闪烁
系统提示：使用中性色，短句，不覆盖关键状态
```

## 数值变化 UX

所有数值加减使用统一反馈规则。

```text
数值增加：绿色 +N，短暂上浮或向右轻移，随后淡出
数值减少：红色 -N，短暂下沉或轻微闪烁，随后淡出
中性变化：灰色 ±0 或淡入更新
资源收益：绿色，并显示来源
资源消耗：红色或橙色，并显示原因
风险升高：黄色到红色，并伴随短时高亮
风险降低：蓝绿色，并使用弱动效
重大变化：允许更强高亮，但仍遵守同一持续时间和位置规则
```

示例：

```text
Water  0.8 days   -0.2  because of heat
Raft   73%        -8    after failed salvage
Food   2.1 days   +0.6  from fishing
Risk   Medium     ↑ High
```

## 上浮提示规则

上浮提示用于临时反馈，不能替代常驻状态。

```text
出现位置：贴近发生变化的数值或事件源
持续时间：短暂显示后自动消失
数量限制：同一区域同时最多显示少量提示
内容格式：变化值 + 原因
优先级：危险提示覆盖普通提示，重大事件覆盖资源变化
```

示例：

```text
-12 Energy  salvage attempt
+0.4 Water  rain collected
Storm Risk ↑  wind changed
```

## UiEvent 生命周期

TUI 表现层统一消费 `UiEvent`，而不是直接读取规则结算细节来决定动效。

```text
created_frame：事件进入 TUI 表现层的帧
ttl_frames：事件可见帧数
motion：none / fade / pulse / rise / sink / slide
visibility：timed / persistent
intensity：根据当前帧和 ttl 计算 1.0 到 0.0
```

生命周期规则：

```text
普通日志：短 ttl，fade
数值增加：中等 ttl，rise
数值减少：中等 ttl，sink
风险变化：较长 ttl，pulse
fallback：较长 ttl，pulse
重大事件：较长 ttl，slide
本地控制提示：中等 ttl，slide
```

Activity 区域只展示仍在可见生命周期内的 UiEvent。TUI 可以用 intensity 控制亮度、标记或未来的插值动画。

## 事件与日志动效

```text
新事件：从事件区进入，短时高亮事件标题
agent 思考中：当前 Agent 区显示轻量等待态
agent 做出选择：选择项高亮，理由随后出现
结算完成：状态变化与日志同步出现
新日志：淡入或从底部进入，旧日志自然上移
重大日志：标题短时高亮，正文保持稳定
```

## 风险与危险状态

```text
注意：黄色，用于资源偏低、天气转差、体力不足
警告：橙色，用于资源不足、船体受损、风险升高
危急：红色，用于濒死、脱水、风暴、木筏严重损坏
恢复：蓝绿色，用于风险下降、状态回稳、资源补充
```

危险提示应短时突出，随后保留在对应状态项上，避免长时间闪烁造成疲劳。

## 刷新与节奏

```text
基础 tick：状态轻量刷新
事件触发：事件区、Agent 区、日志区依次更新
结算瞬间：相关数值显示加减反馈
平稳期：界面保持低动效，仅显示倒计时、时间和环境变化
暂停状态：整体动效停止，保留当前画面和日志
```

界面节奏应形成：

```text
平稳观察 → 事件出现 → agent 判断 → 结算反馈 → 回到平稳观察
```

## 控制规则

MVP 键位：

```text
q / Esc：退出
p / Space：暂停或继续
```

TUI 是观察窗口，不负责提交游戏行动。策略行动由外部 agent 通过 MCP 提交。TUI 在 pending decision 时显示等待 agent 和可选 action id。

## 中文与多语言排版

中文 TUI 排版需要作为渲染层基础能力统一处理。

```text
显示宽度：使用 terminal display width，不使用字符数
字素切分：按 grapheme cluster 截断，避免切断组合字符
中英文混排：英文、数字、中文、符号混排时保持列宽稳定
中文换行：允许按显示宽度换行，不依赖空格
英文换行：优先按单词换行，过长单词按显示宽度截断
省略号：截断时按显示宽度预算插入 ellipsis
表格对齐：所有单元格 padding 按显示宽度计算
上浮提示：提示框宽度按本地化后的文本重新测量
```

风险点：

```text
中文字符通常占 2 列
emoji 和部分符号可能占 2 列或受终端影响
全角标点和半角标点混用会影响视觉密度
不同终端字体会让边框和 CJK 文本观感不同
```

MVP 规则：

```text
默认语言：zh-CN
默认边框：使用 Ratatui 标准边框
中文正文：允许自然换行
状态名：优先使用短标签
数值列：固定宽度，文本列弹性宽度
日志正文：按显示宽度 wrap
关键面板标题：从 locale key 获取，不写死
```
